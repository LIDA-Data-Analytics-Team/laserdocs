## Use of MESH

### Preparing files for transfer  

PICANet team will create for us a list of NHS numbers that need to be screened for opt-outs. 

Each transfer consists of 2 files  
- a .dat file - this is the data file (payload) and contains the data you wish to send  
- a .ctl file - this is the control file and provides the required information for MESH to route the message to the correct recipient  

Both files must have the same name for the message to send correctly (and the given .dat or .ctl file extension at the end). For example, to send a file, you would need both a NHSD_26092019_1120.ctl and a NHSD_26092019_1120.dat file.    

The naming convention for the files is as follows:
- 8KM29_Date_Time.csv.dat
- 8KM29_Date_Time.csv.ctl

Once created (see below) both files need to be placed in the 'out' folder on DAT02:  
`C:\dat\MESH\MESH-DATA-HOME\8KM29HC001\out`.

Make sure that the .dat file is moved to 'out' before the .ctl file, otherwise the MESH client might pick up the .ctl and fail the transfer before the .dat file is present.  

The .dat file contains the data in .csv format but with a .dat extension. It must contain just NHS Numbers in a single column separated by a comma and followed by a carriage return; [eg](https://digital.nhs.uk/services/national-data-opt-out/compliance-with-the-national-data-opt-out/check-for-national-data-opt-outs-service/format-of-nhs-number-data-file):  
```
9000543664,
9000956406,
9000617017,
etc

```

The .ctl file contains the meta data for the transfer. The only bit you may want to edit is the LocalId. Give a LocalId that helps identify the request, e.g. the PICANet data request name/ID. Example below and template in the 'out' folder.  
```
<DTSControl>
<Version>1.0</Version>
<AddressType>DTS</AddressType>
<MessageType>Data</MessageType>
<WorkflowId>SPINE_NTT_UPHOLDING</WorkflowId>
<To_DTS>X26HC065</To_DTS>
<From_DTS>8KM29HC001</From_DTS>
<Subject>P0001-PICANet</Subject>
<LocalId>**INSERT ANY PICANet REFERENCES HERE**</LocalId>
<Compress>Y</Compress>
<AllowChunking>Y</AllowChunking>
<Encrypted>N</Encrypted>
</DTSControl>
```

### Sending files  

Once files have been created and placed in the 'out' folder run **runMeshClient.bat**. To run the batch file you may have to be running as Administrator. Search 'cmd' in the Start Menu, then right-click and select Run as administrator.

In your new cmd session, change directory to the MESH app:
`cd C:\MESH-APP-HOME\`

Then run the batch file:
`runMeshClient.bat`

This will open a CMD application that will process the files. 

They will be transferred and removed from the 'out' folder and a new .ctl file with the same name created in the 'sent' folder. This new file can be checked for status of the transfer. We're looking for  
```
<StatusRecord>
	<Status>SUCCESS</Status>
	<Description>Data Transfer success confirmation</Description>
</StatusRecord>
```

Any other status will need to be investigated as appropriate.  
[Error messages and failure to send](https://digital.nhs.uk/services/message-exchange-for-social-care-and-health-mesh/mesh-guidance-hub/client-user-guide#error-messages-and-failure-to-send)

### Receiving files  

Files will be processed by the NDOP service and returned via MESH in to the 'in' folder, usually within the hour.  
`C:\dat\MESH\MESH-DATA-HOME\8KM29HC001\in`.  

There will be an initial .ctl file, followed by a .ctl and a .dat file pair, followed by another .ctl and .dat file pair. The latest .dat file contains the returned data, all others are status logs.  

The MESH client will need to be running for the returning transfers to take place.  

MESH will delete messages that haven't been downloaded 5 days after they have been sent, as the default configuration of MESH client does not send a notification of receiving a new message.  

Once received, make available to PICANet team so they can create the research extract.
