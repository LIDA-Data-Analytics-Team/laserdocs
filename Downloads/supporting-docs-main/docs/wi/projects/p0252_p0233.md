# P0252 TRACK & P0233 Leeds Lifeband

## Import data from data partners via SCP

### P0252

#### File transfer

- Data comes from wristband data partner and is pulled into TRACK's tier 4 LASER VRE via SCP
- At time of writing (2022-11-04) transfers are not taking place, but we're set up to start as soon as the project is ready
- When the project are ready to perform these transfers, we agreed to transfer the data on a weekly basis
- This can be done manually at the moment, but it is proposed we automate this in future
- There is a Bash script stored on DAT02's incoming share that runs the transfer
- To run the file transfer script open Git Bash, type the line below then press enter<br>
`//datstagingdata.file.core.windows.net/incoming/P0252v01\ \(safe\ room\)/_importer/p0252v01_importer.sh`
- This script:
    - creates a datestamped folder in p0252v01's folder on incoming share
    - using the scp command, the data is transferred from Impli's server to the newly created folder on our incoming share
    - the scp command transfers data via an SSH session, which is set up using the user created for us on Impli's server and an SSH key we gave to Impli
    - the key we gave to Impli is stored in<br>
    `//datstagingdata.file.core.windows.net/incoming/P0252v01\ \(safe\ room\)/_importer/.ssh/`
    - the Bash script then logs the transfer date in a temp file and sends this to Impli's server so they know when we last grabbed data
    - lastly the data is transferred from DAT02's incoming share to p0252v01's project share

#### Automation

- A scheduled task has been created to run the Bash script, but it currently doesn't work
- The scheduled task is set up to run the script daily
- The task runs authenticated as LASER's file transfer service account, zz_laser-ft
- I think the scheduled task doesn't work because the service account hasn't been assigned appropriate Azure roles to access datstagingdata and azlrdpp0252v01 storage accounts and their file shares. It would need to write permissions on DAT02's incoming share and p0252v01's project share.
- To create the scheduled task from scratch:
    - Open Task Scheduler on DAT02 and click Create Task...
    - Give the task a name and description if you want
    - By default the task will run using your account, which is fine when testing so you may leave it as is for now, but there are steps below to edit the created task so that it runs using the service account mentioned above
    - Configure for Windows Server 2019 by selecting that OS from the dropdown
    - Now on the Triggers tab, create a new trigger with your chosen frequency etc. (daily at set time)
    - On the Actions tab, click New...
    - The action will be to "Start a program"
    - The program is `C:\Program Files\Git\git-bash.exe`
    - In the Add arguments field, enter the file path to the Bash script you want to run, e.g.
    `//datstagingdata.file.core.windows.net/incoming/P0252v01\ \(safe\ room\)/_importer/p0252v01_importer.sh`
    - Click OK
    - If you want, on the Settings tab you can tell the task to retry on failure etc.
    - Create the task by clicking OK
    - You can test the task by either clicking the run button or setting its trigger to one minute in the future
- To set the task to run using the LASER file transfer service account:
    - Open the task and on the General tab, click the Change User or Group... button
    - Find the service account then click OK
    - Still on the General tab, select the radio button to "Run whether the user is logged on or not"
    - We want the task to have access to more than local resources, so leave unchecked the box that says "Do not store password..."
    - Select the checkbox to "Run with highest privileges"
    - Click OK on the General tab. You'll need to authenticate using the service account's password, which Server team can provide. 

### P0233

- Lifeband project needs exactly the same treatment as TRACK P0252
- This has not been set up yet because the project has been heavily delayed
- Lifeband plans to receive very similar data, flowing in very similar ways, from multiple data partners (one for data generated from wristbands, another for essentially the same data generated from mobile apps)
- When the time comes to set this up, you could copy P0252v01's _importer/ folder to P0233's folder, then create replace the SSH key and tweak the Bash script to connect to the correct server and transfer files to the correct file shares.
- Create new SSH keys and scripts for each data partner
- You can follow the steps above to automate these scripts using Task Scheduler
