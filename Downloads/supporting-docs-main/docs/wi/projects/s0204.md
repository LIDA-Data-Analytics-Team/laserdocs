# S0204 YCRBCIP

## S0204 data flows

DAT need to conduct several regular, timely file transfer for S0204 YCRBCIP. This work instruction describes what to do.

- [Weekly](#weekly)
- [Monthly](#monthly)
- [Ad hoc](#ad-hoc)
- [Ad hoc](#ad-hoc)

## Weekly

Weekly transfers are scheduled on Tuesday mornings.

Check the DAT calendar and mention in the DAT Teams chat when you're taking responsibility for the week's transfers, so everybody knows it's getting done.

### New patient data

1. Maintenance throughout the week
    1. New patient data will arrive throughout the week from the 11 hospital sites. These will come from a known set of sites/recipients, listed at:<br>
    `"\LASER\Projects\S0204 - YCRBCIP\YCRBCIP_new_patients_death_checks_Site email addresses 270422.docx"`
    1. When we get Biscom notification emails in the team inbox, file them as unread emails into `Projects/S0204 - YCRBCIP/YCRBCIP scheduled transfers` folder. When they're taken care of as part of the weekly transfer, they can be marked as read and moved into the project folder, Projects/S0204 - YCRBCIP.
    1. Try to leave the Biscom deliveries as unread until the weekly transfer takes place.
1. Download from Biscom
    1. Each hospital site has their own permanent Biscom delivery that they can reply to. Some sites have multiple recipient addresses. The permanent deliveries containing patient data all follow the same naming convention:<br>
    `Re: Import YCRBCIP files (<site-name>)`
    1. Log into Biscom on DAT02 using the team account and download any data files sent via permanent deliveries _since the last weekly transfer_. Don't only download files from unread messages, as some could get read before they're transferred. Make a folder called today's date at `I:\S0204v01\<today-date>\` and download the files to this folder.
    1. Check that the files contain expected data - details of consented patients. If not, identify whether the file pertains to a different data flow. If the file doesn't belong to any documented data flow, query it with the project team first so that they can liaise with the hospital site.
1. Transfer to tier 4
    1. Copy the patient data files to the tier 4 VRE in a date-stamped folder at:<br>
    `\\azlrdps0204v01.file.core.windows.net\project\StudyAdmin\_incoming\new_patients\<today-date>\`
1. Transfer de-identified copies to tier 3
    1. Go to `I:\S0204v01\_new_patients_processing\` and double click `_new_patients_processing.Rproj`
    1. From RStudio, open script called transfer_new_patient_data.R
    1. Follow the instructions in this script to edit the list of file paths, to point to the new patient data. It is recommended to run each chunk of script separately.
    1. Run the edited script, which will create de-identified copies of the patient data and save them to the tier 3 VRE at:<br>
    `N:\project\ProjectTeam\_incoming\nihr_consents\<today-date>\`
    1. The tier 3 files will have the same names as the tier 4 files, but with a "_deidentified" suffix
    1. The tier 3 files should contain the same number of Excel sheets as the tier 4 files. Each sheet should contain the same number of rows as its tier 4 equivalent. The tier 3 sheets should contain participant ID (PartID), date consented (DateConsRef), whether consented or refused (Consent), and a comments field (Comments). The consent dates may contain improperly formatted dates - as long as they're the same as the tier 4 equivalent, that's ok.
1. Record file transfers in the audit log if you haven't done so already
1. Let the project team know that the week's batch of patient data has been transferred, either via Teams chat or email 

### Import returned death checks

1. We [send death checks](#send-death-check-requests) to sites on a monthly basis. The project team ask sites to return death checks within seven days, however some may come in late. Check for returned death checks and import on a weekly basis.
1. When we get notification emails in the team inbox, file them as unread emails into `Projects/S0204 - YCRBCIP/YCRBCIP scheduled transfers` folder. When they're taken care of as part of the weekly transfer, they can be marked as read and moved into the project folder, Projects/S0204 - YCRBCIP. Try to leave the Biscom deliveries as unread until the scheduled transfer takes place, but if any are read since last scheduled transfer make sure to not miss them.
1. Import all newly returned death checks into a date-stamped subfolder in<br>
`\\azlrdps0204v01.file.core.windows.net\project\StudyAdmin\_incoming\death_checks`
1. Record file transfers in audit log and update project team

### Update questionnaire status in tier 4

1. Project team update spreadsheet in tier 3 at `N:\project\ProjectTeam\_outgoing\questionnaire_status_for_tier4\`. The spreadsheet is protected to minimise risk of unauthorised transfer between tier 3 and 4.
1. Check if there is an update to the questionnaire status since the last weekly transfer
1. During the weekly schedule, DAT then copy spreadsheet from tier 3 location to tier 4 VRE at `N:\StudyAdmin\_incoming\questionnaire_status\`. The previous version can be overwritten. Remember to remove the security protection in the data staging area before sending to tier 4.
1. Let project team know the tier 4 version has been updated
1. Record file transfer in audit log

In future, the spreadsheet will be put into a code share. Then the project team can update from tier 3 and the changes will be visible in tier 4 immediately, without any assistance from DAT. The spreadsheet is protected, and with data validation, to reduce risk of unauthorised transfer between tiers 3 and 4. The code share permissions will also be locked down to limit what users can do. Request for code share has been submitted.

### Letters to secure printer

1. Project team will put letters for printing in the tier 4 VRE at `N:\StudyAdmin\_outgoing\letters_to_print\` in a date-stamped subfolder.
1. Open each letter in Word, go to File > Print section
1. If no printers found, restart print spooler. See [secure printing WI](../secure_printing.md) for more details.
1. Select the secure printer and click printer properties
1. Go to the Job storage tab, enter a PIN then click OK
1. Print letter
1. Enter PIN again in next dialog box and OK the next notification (if it appears).  
1. Repeat for all letters using the same PIN
1. Let project team member, usually Emily Connearn, know that the letters are ready to be printed. Make sure to give Emily the PIN and it may help her to also know which username will contain the print jobs on the printer screen (also specified in the job storage properties tab).
1. Record file transfers in audit log

### Phone conversations

1. These requests can be dealt with as per the weekly schedule, except [study withdrawals](#study-withdrawal-phone-calls) which should be handled as urgent as hoc requests.
1. Patients, relatives or hospital site call project team (Hannah) to request a change or update to the patient's status. Project team will use a permanent Biscom link while on the phone to send phone conversation details into LASER and let DAT know that the request has come in. The permanent Biscom thread's subject title is "YCRBCIP Telephone Requests".
1. Import to the tier 4 VRE at `N:\StudyAdmin\_incoming\phone_requests\`, saving to a file named `phone_request_YYYYMMDDHHMM.txt`, where YYYYMMDDHHMM is the date and time the Biscom message was sent.
1. Project team will pick up the request file and action as needed. The request may need a response, in which case the project team can edit the file to add a response and append "_response" to the file name, e.g. `phone_request_YYYYMMDDHHMM_response.txt`.
1. Send the edited file into the permanent Biscom thread so that the project team can respond to the patient.
1. Record file transfers in audit log and update project team

## Monthly

Monthly transfers take place on the first Thursday of the month. Follow up transfers may be required on the second Thursday of the month (e.g. send death check requests in week 1, import returned death checks in week 2).

### Send death check requests

1. Go to `\\azlrdps0204v01.file.core.windows.net\project\StudyAdmin\_outgoing\death_checks`
1. A date-stamped subfolder will contain the death checks to be sent to hospital sites this month
1. Send the files in this folder to their respective hospital sites using Biscom
    1. Each site's recipient email addresses are registered Biscom contacts and can be found in<br>
    `N:\Academic-Services\ISS\IRC-Data-Services\Projects\S0204 - YCRBCIP\YCRBCIP_new_patients_death_checks_Site email addresses 270422.docx`
    1. Use subject `YCRBCIP death checks (<site-name>)`
    1. Message template<br>
    ```
    Dear <site-name> team,

    Please find attached new death checks from YCBCIP study.

    Thanks,
    LIDA Data Analytics Team
    ```
    1. Include all site recipients if the site has multiple email addresses
1. Record file transfers in audit log and update project team

### Questionnaire response data

1. Project team will request to import questionnaire responses into tier 3 VRE.
1. Send project team a Biscom link
1. They will import pseudonymised, coded questionnaire responses
1. Import into tier 3 VRE at project team's chosen destination or<br>
`\\azlrdps0204v02.file.core.windows.net\project\_incoming\questionnaire_responses`
1. Record file transfers in audit log and update project team

### Send tissue requests

1. Project team will request DAT to export tissue requests from chosen folder, or files located in dated subfolder at<br>
`\\azlrdps0204v01.file.core.windows.net\project\Pathology\_outgoing\tissue_requests`

    1. Each site's recipient email addresses are registered Biscom contacts and can be found in<br>

    1. Message template<br>
    ```

    Please find attached new tissue requests from YCRBCIP study.

    Thanks,
    LIDA Data Analytics Team
    ```
    1. Include all site recipients if the site has multiple email addresses
1. Record file transfers in audit log and update project team

### Import returned tissue requests

1. Hospital sites return processed tissue requests to Pathology Department via NHS.net redacted of patient identifiers. Pathology sends confirmation of pseudonymous tissue receipts to LASER via NHS Egress or Biscom.
1. Project team will request these to be imported, then we can invite them to use Biscom or Egress
1. Import tissue receipts into tier 4 VRE at project team's chosen destination or<br>
`\\azlrdps0204v01.file.core.windows.net\project\Pathology\_incoming\tissue_receipts`
1. Record file transfers in audit log and update project team

## Ad hoc

Some of the ad hoc requests that we'll get. Not a complete list. The usual project imports/exports will apply.

### Study withdrawal phone calls

1. Deal with these as you would other [phone call requests](#phone-conversations), except the project team will use a separate permanent Biscom thread just for withdrawals, and these should be dealt with urgently

### PROMS queries

1. Hospital sites email Emily with queries about patients and questionnaires, giving pseudonymous IDs. Where the query response requires the admin database, the project team will use a permanent Biscom link to send the query to DAT. The permanent Biscom link's subject title is "YCRBCIP Proms Queries (S0204)".
    1. Occasionally Emily will have queries for hospital sites. The below process can effectively work in reverse.
1. Import the query details into the tier 4 VRE at `N:\StudyAdmin\_incoming\proms_queries\`, saving to a file named `proms_query_YYYYMMDDHHMM.txt`, where YYYYMMDDHHMM is the date and time that the Biscom message was sent.
1. Project team will pick up the request file and action as needed. The request may need a response, in which case the project team can edit the file to add a response and append "_response" to the file name, e.g. `proms_query_YYYYMMDDHHMM_response.txt`.
1. Send the new file into the permanent Biscom thread so that the project team can respond as needed.
1. Record file transfers in audit log and update project team

### Pathology reports

1. Pathology team contacts DAT to request Biscom link, specifying what files will be transferred. DAT share Biscom link.
1. Import files into tier 4 VRE at `N:\Pathology\_incoming\pathology_reports` in a dated subfolder.
1. Record file transfers in audit log and update project team

### NCRAS

1. Pseudonymous tier 3 NHS data from National Disease Registration Service data, containing: Hospital Episodes Statistics, National Cancer Registration, Diagnostics Imaging Dataset, Systemic Anti-Cancer Therapy Dataset, National Radiotherapy Dataset, Pathology Dataset. 
1. DSA required to cover data transfer from NHS entities to LASER - check DSA during transfer
1. Follow data provider requirements for data transfer, otherwise send them Biscom link
1. Import files into tier 3 VRE at `N:\_incoming\ncras\`
1. Record file transfers in audit log and update project team
